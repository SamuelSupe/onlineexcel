## 明显缺陷修复回归（2026-09-20）

本轮先运行复现用例，再修复编辑状态、可见区域读取和数字渲染。修复前确认：公式栏草稿切换后为空；编辑 J7 时调用 select(J8) 会把 42 写到 J8；普通文本 =1+1 在 F2/Enter 后变为 2；只读公式栏 Enter 增加工作簿版本；10 万行筛选仅剩第 1、50001、100000 行时读取超出 200,000 单元格上限；30 位小数格式触发 RangeError。

修复后：

- 单元格与公式栏共用绑定原始地址的草稿；切换选区、失焦和工具栏操作先提交，Esc 取消，未修改内容不产生写入。
- 普通等号文本保持文本，文本格式输入不被当作公式；只读公式栏不发起写入。
- 筛选或隐藏造成的可见行列间隔被拆分，重叠预读区域合并，并按 Worker 单次读取上限分块。
- 数字与科学计数法显示最多使用 20 位小数，保留文件中的原始格式，避免超长精度使网格渲染抛错。

OrbStack 完成 154 项行为测试、类型检查与发布构建。Chrome 构建产物集成页的编辑回归、10 万行稀疏筛选、五语言、只读、多实例、撤销事务、导入取消及文件往返全部通过；真实 Chrome 重跑公式栏点击加粗后得到 30、普通文本 F2/Enter 后仍显示 =1+1，控制台无错误。本轮未重跑百万单元格性能基准，也未新增桌面 Excel 实机验收。

### 第四轮：条件数组、查找、事务和地址输入

OrbStack 先复现了以下错误：`IFERROR({#N/A;#N/A},{10;20})` 得到 10、10；`IF({TRUE;FALSE},{1,2},{3,4})` 丢失第二列；精确查找文本 `>5`、`>=x` 时将其误作比较条件；在同一事务中重定义命名区域后，仅复制值仍读取旧计算结果。

修复后，IF/IFERROR/IFNA 按对应位置读取数组分支并扩展单行、单列维度，保留未使用分支的延迟求值。精确查找将比较符视为文本，按查找函数规则处理通配符，并区分数字与数字文本。事务中的复制和排序会先重算命名区域等结构变化。数组错误替换与查找语义参考 Microsoft 的 [IFERROR](https://support.microsoft.com/en-us/excel/functions/iferror-function) 和 [MATCH](https://support.microsoft.com/en-us/excel/functions/match-function) 文档；该轮没有桌面 Excel 实机对照结果。

Chrome 连续操作另外复现了地址输入竞态：较早的地址跳转回调抢走新草稿焦点，延迟的程序滚动事件提前提交草稿，后台刷新覆盖尚未提交的地址文本。现在只有地址框仍持有焦点时才自动切回网格；编辑开始时记录滚动位置，无位移的旧滚动事件不会提交草稿；地址框持有焦点时保留用户输入，失焦后恢复实际选区地址。回归同时确认真正滚动仍会提交草稿。

OrbStack 的 180 项测试（模型 24、公式 147、文件 9）、类型检查和发布构建通过。Chrome 构建产物集成页覆盖上述公式、事务、XLSX 往返和地址输入回归，连同已有五语言、只读、多实例、剪贴板、撤销及导入取消检查全部通过。真实 Chrome 连续输入 IFERROR 数组后跳转 D21 显示 20，输入二维 IF 数组后跳转 H21 显示 4；截图确认结果区域正常，控制台无错误或警告。本轮未重跑性能、其他浏览器、系统 IME 候选窗口或桌面 Excel 验收。

### Chrome 编辑和滚动

最终结果：Worker 加载 2,864.9 ms，编辑反馈 P95 **23.3 ms**，滚动 **120.0 FPS**，帧间隔 P95 9.7 ms；视口 1456 × 481 CSS px，DPR=2。原始记录见 [benchmark-browser.json](benchmark-browser.json)。编辑耗时从 API 写入开始，等待编辑器的活动单元格反映结果，再等一帧绘制，包含 Worker 往返与 UI 更新。30 次编辑取 P95。滚动使用 180 帧连续改变滚动位置，网格持续实际绘制；显示刷新率约 120 Hz。

验收目标为滚动 ≥50 FPS、普通编辑反馈 P95 ≤100 ms；本数据集达到这两个目标。结果仅适用于记录中的硬件、Chrome、视口和工作负载。
